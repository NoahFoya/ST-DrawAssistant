# ST-DrawAssistant 项目开发规划

> **重要说明**：本文档为**开发参考框架**，旨在为项目推进提供结构化的思路指引，而非必须严格遵循的“施工蓝图”。实际开发中，应根据需求变化、技术探索中发现的新情况灵活调整优先级和实现路径。**以实际开发需求为准**，文档服务于开发，而非束缚开发。

## 一、项目概述

| 项目信息 | 内容 |
|---------|------|
| **项目名称** | ST-DrawAssistant |
| **项目类型** | SillyTavern 文生图扩展插件 |
| **核心功能** | 在 SillyTavern 聊天界面中，通过 AI 生成与对话上下文相关的图像 |
| **技术架构** | 浏览器端 UI 扩展（核心）+ 可选 Node.js 服务端插件（增强层） |
| **主要集成** | ComfyUI、Stable Diffusion WebUI 等图像生成后端 |

### 1.1 设计原则

1. **UI 扩展独立运行**：核心功能不强制依赖服务端插件，降低用户安装门槛
2. **多后端支持**：通过驱动模式抽象，支持切换不同的生图引擎
3. **存储与消息解耦**：图像数据存 IndexedDB，消息仅存 UUID 引用，避免聊天文件膨胀
4. **渐进增强**：服务端插件作为可选增强层（代理请求、隐藏 API Key），不影响核心功能
5. **主题自适应**：引用 SillyTavern 主题 CSS 变量，自动适配亮/暗色主题

### 1.2 开发环境

- **Node.js**：>= 20.0.0
- **包管理**：npm / pnpm
- **构建工具**：Webpack（参考 SillyTavern WebpackTemplate）
- **开发目录**：`SillyTavern/public/scripts/extensions/third-party/ST-DrawAssistant/`
- **代码管理**：`.agent/` 文件夹为本地开发辅助框架（AGENTS.md + Skills），**已在 .gitignore 中忽略**，不纳入版本库

## 四、关键决策备忘

| 决策点            | 建议                             | 理由                                                         |
| ----------------- | -------------------------------- | ------------------------------------------------------------ |
| **默认 Provider** | ComfyUI                          | 文生图插件常用，支持 Workflow 自定义，社区活跃               |
| **并发策略**      | 单任务串行（可配置最大并发 1-3） | ComfyUI 执行时资源占用高，串行避免 CUDA OOM                  |
| **存储方案**      | IndexedDB + UUID 引用            | 聊天文件保持轻量（KB 级），避免 JSONL 膨胀至数十 MB          |
| **服务端插件**    | 可选，不强制                     | 降低安装门槛，满足官方审核要求                               |
| **事件触发生图**  | 默认关闭，用户手动开启           | 避免用户意外消耗配额或产生意外内容                           |
| **取消策略**      | 客户端丢弃模式                   | ComfyUI 不支持精确取消 RUNNING 任务，此模式是官方能力下的最佳实践 |

## 六、架构灵活性声明

1. **本文档为开发参考，非硬性契约**：实际开发中可根据需求变化、技术探索结果灵活调整任务优先级和实现路径。

2. **建议从 P0 阶段的核心功能开始**，尽快实现端到端的生图流程（点击按钮 → 生图 → 展示），再围绕核心功能逐步完善外围能力。

3. **服务端插件为可选增强**：建议在 P2 阶段再考虑实现，或者根据用户反馈决定是否开发。

4. **驱动可扩展**：如需支持新的生图后端，只需新增实现 `ImageDriver` 接口的类，并在工厂中注册即可，无需修改核心逻辑。

5. **UI 可独立演进**：设置面板、楼层按钮、图库视图等 UI 组件与核心逻辑解耦，可根据用户反馈独立优化。
